# DESS

Configurable academic management application. An institution describes its organizational
structure in XML; the academic concepts and business rules stay explicit in Java.

The MVP delivers one usable path, from setup to results:

1. Import an institution structure from XML.
2. Register people, academic periods, student groups and program enrollments.
3. Define courses, course offerings and teaching assignments.
4. Schedule a teaching session; reserve its room, teacher and group; reject conflicts.
5. Create an assessment and schedule an exam session through the same booking service.
6. Record and retrieve results.

> **Status: skeleton.** This repository was generated by `create-dess.sh`. The structure, build files,
> contracts and a few domain rules are in place; the features are not implemented yet.

## Architecture in one page

A **modular monolith** (one deployable WAR) organised as **DDD bounded contexts**, with a REST API,
PostgreSQL and an optional React frontend. Full details: [docs/architecture.md](docs/architecture.md).

| Module | Role | Depends on |
|---|---|---|
| `institution` | Institution, organizational units, hierarchy rules, XML import | `shared` |
| `people` | Person, student and professor profiles | `shared` |
| `scheduling` | Rooms, bookings, conflict checks (knows no course or exam) | `shared` |
| `academic` | Periods, groups, programs, enrollments, courses, offerings, teaching sessions | `institution`, `people`, `scheduling`, `shared` |
| `assessment` | Assessments, exam sessions, candidates, results | `academic`, `people`, `scheduling`, `shared` |
| `security` | Accounts and roles (admin, professor) | `people`, `shared` |
| `platform` | WAR: REST application, error mapping, OpenAPI, configuration | all modules |
| `shared` | Shared kernel: IDs, `TimeRange`, base exceptions | none |

Inside every context:

```text
<context>/
  api/               published interfaces: the only package other contexts may import
  internal/
    domain/          aggregates, value objects, domain services, repository interfaces
    application/     use cases (transaction boundary)
    infrastructure/  JPA repositories, adapters, anti-corruption layers, XML parsing
    rest/            Jakarta REST resources
```

Key rules: aggregates reference each other by UUID; no public setters; one repository per aggregate
root; session and booking are saved in one transaction (ADR-006); the database, not only Java, prevents
double bookings (ADR-003). `ArchitectureTest` enforces the dependency rules.

## Getting started

Prerequisites: Java 21, Maven 3.9+, Docker (PostgreSQL), a Jakarta EE 11 server (plan: WildFly 42),
Node.js 22+ for the frontend.

```bash
cp .env.example .env              # then set DESS_DB_PASSWORD
./ops/scripts/start.sh            # PostgreSQL + Flyway migrations
mvn -B -ntp verify                # build and test every module
```

Then configure the datasource and deploy `backend/platform/target/dess.war`
(see [docs/local-setup.md](docs/local-setup.md)). The API is served at `http://localhost:8080/dess/api`.

```bash
./ops/scripts/health-check.sh     # PostgreSQL and server status
./ops/scripts/backup.sh           # database dump in backups/
./ops/scripts/stop.sh
```

Frontend: see [frontend/README.md](frontend/README.md).

## Working rules

- One shared repository. `main` must always build. Short feature branches, merged at least daily.
- At least one review per merge. Module owners approve routine work; the lead reviews cross-module
  contracts and architecture changes.
- Migrations are committed with the feature that needs them, named
  `V<yyyyMMdd>_<HHmm>__<module>_<description>.sql`, in `backend/<module>/src/main/resources/db/migration/<module>/`.
- Tests use PostgreSQL through Testcontainers, not an in-memory database.
- Never access another module's repository or tables directly. XML import goes through the `institution` application service.
- A feature is done when it works through the application layer, persists, validates its inputs, has success
  and failure tests, builds on the latest `main`, and runs in the local application.
